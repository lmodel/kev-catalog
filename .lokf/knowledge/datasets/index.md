# Datasets

* [kev-catalog LinkML schema](kev-catalog-linkml-schema.md) - The LinkML schema of the JSON format of the Known Exploited Vulnerabilities (KEV) catalog, `src/kev_catalog/schema/kev_catalog.yaml` (schema id `https://w3id.org/lmodel/kev-catalog`, version 2026-09-17): the classes `KevCatalog` and `KevVulnerability`, CISA's keys as its slots, and two enums. Its `lokf adapt` copy `.lokf/kev-catalog.yaml` is the bundle's domain schema.
* [The pinned KEV catalogue release](pinned-kev-catalogue-release.md) - The release of the KEV catalog that the tests pin: `catalogVersion` 2026.10.30, released 2026-10-30, with a count of 1,766 entries, fetched from `cisagov/kev-data` at commit `7ccba8e1223c` and validated in full by `just test-kev-data`. This concept lists no entries inline.
* [The entry for CVE-2021-44228](worked-entry-cve-2021-44228.md) - The KEV catalog's entry for CVE-2021-44228, Apache Log4j2, as a worked example of an entry with every key. It is copied from the pinned catalogue into `tests/data/valid/KevVulnerability-every-key.yaml` and the extract.
* [Generated artefacts](generated-artefacts.md) - What the LinkML generators write from the schema: `project/` (JSON Schema, OWL, SHACL, ShEx, JSON-LD and others), the Python models in `src/kev_catalog/datamodel/`, and the merged schema in `docs/schema/`. They are never edited by hand.
* [Example data](example-data.md) - The examples the tests hold the schema to, under `tests/data/`: valid examples, counter-examples that each name the JSON pointer they fail at, a folder for valid data the generated dataclasses refuse, and the pinned catalogue's manifest and twelve-entry extract.
* [Upstream copies](upstream-copies.md) - The exact copies of CISA's files under `tests/upstream/`: the JSON schema and the licence of the mirror, each held to its pin by `tests/test_upstream.py`. The test walks the JSON schema, and fails on any part with no element in the LinkML schema.
* [Neighbours' adapt copies](neighbour-copies.md) - The adapt copies of other lmodel repositories under `tests/neighbours/`, each pinned by its SHA-256 in `tests/test_schema_rules.py`. The test holds this repository's copy apart from them and from LOKF, so that a new shared name fails.
